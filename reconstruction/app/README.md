# 졸음운전 방지 카메라 — 최종발표 우선 코드 복원본

이 저장소의 2023년 최종 발표자료(8장) 3번 슬라이드의 **3단계 흐름도**를 기능·분기의 최상위 기준으로 하며, `src/`의 **2023년 실제 원본 소스**에 나타난 산식과 API 사용 방법을 가능한 한 계승합니다. 그 이후 당시 개발 질문·답변의 수치를 반영하고, 그래도 알 수 없는 부분만 `docs/TRACEABILITY.md`에 추정으로 표기했습니다. 원본 `src/` 10개 파일은 변경하지 않았습니다.

## 확인된 동작 순서

1. 눈 특징점을 인식해 EAR과 눈 y위치로 감지: **얼굴형을 따로 분류하지 않음**. dlib 얼굴 검출은 눈의 68개 특징점을 찾기 위한 선행 위치 추정일 뿐 얼굴 형태로 졸음을 판정하지 않습니다. 사용자 회고에 따르면 안경·선글라스에서도 작동했습니다(조건별 인식률 수치는 없음).
2. 1단계 감지: 경고음 `wa.wav → warning.wav`.
3. 2단계 감지: 경고음 `da.wav → danger.wav` 이후 **하나의 수학 문제**를 제시하고 약 **10초 동안 음성 입력**을 받아 STT로 정답을 판별. **오답·미인식이면 같은 문제를 해결할 때까지 제한 없이 반복**.
4. 3단계 감지: 경고음 `da.wav → decibel.wav` 이후 **음량 기준을 넘을 때까지 측정 반복**(최대 3회라는 임의 제한 제거).
5. **3단계 해결 후 다음 감지는 1단계**. 각 단계가 끝난 뒤 영상 인식을 재개하며 경고 중에는 추가 영상 연산을 하지 않습니다.

> 여기서 '약 10초'는 **마이크로 음성을 받는 구간**입니다. 이전 재구성본이 Google TTS/STT API 네트워크 요청에 별도로 부과한 `timeout=10.0`은 근거가 없는 기술 설정이라 삭제했습니다.

## 핵심 파일

- `main.py`: 하나의 진입점, 감지·경고 순서 연결
- `drowsiness/vision.py`: 원본 `test_v2.py`의 EAR/눈 위치 수식을 사용, 3초 초기 평균은 후기 개발 대화에서 보완
- `drowsiness/stages.py`: 1→2→3→1 상태 전환, 미해결 시 단계 유지·무제한 재시도
- `drowsiness/quiz.py`: 원본 `test1.py`, `222.py`를 참고한 Google TTS/STT 수학 문제 반복. 문제는 성공할 때까지 동일하게 유지
- `drowsiness/loudness.py`: 원본 대화의 `20 log10(raw PCM RMS/1)` 음량 계산, 기준값 70
- `drowsiness/camera.py`: Picamera2 영상 입출력
- `config.ini`: 확인된 값과 추정 값을 명시한 설정
- `tests/`: 카메라·마이크 없이 평가 가능한 상태 전환 테스트

## 하드웨어 없이 테스트

```bash
cd reconstruction/app
python3 -B -m unittest discover -s tests -v
python3 -B main.py --demo
```

`--demo`는 세 단계가 해결되는 **가짜 답·가짜 음량 입력**만 사용하는 논리 시뮬레이션입니다. 실제 음성·영상 인식 성능을 검증하지 않습니다. 시험에 필요한 모델과 WAV 파일 등은 포함하지 않습니다.

## 원본과 추정의 경계

- 실제 2023년 `test1.py`는 **스트리밍 STT**를 시험했고 `222.py`는 녹음 후 STT를 시험했습니다. 현재 통합본은 약 10초 음성을 녹음하고 Google STT의 단발 인식 경로를 사용하는 **재구성 어댑터**입니다. 원본 통합 파일이 유실되어 어느 방법이 최종 선택됐는지는 확정하지 않았습니다.
- 최대 얼굴 선택, 얼굴 유실 시 카운트 처리, 오류 예외 처리 등은 코드 연결을 위한 **2026년 추정·보완**이며 원본 기능으로 간주하지 않습니다.
- '무한 반복'은 **문제 미해결·음량 미달이라는 정상 입력 결과**에 적용합니다. 파일·마이크·클라우드 접속 오류는 성공으로 처리하거나 반복 소진으로 다음 단계로 넘어가지 않으며 오류를 별도로 표시합니다.
- Google Cloud TTS/STT 자체는 당시 원본 코드에도 등장하므로 신규 도입한 기능이 아닙니다. 원문과 동일함을 주장하지 않습니다.
