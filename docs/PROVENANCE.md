## 정확히 보존된 사실과 제한

- 2023년 원본 영상 감지 코드는 **얼굴 검출로 눈 랜드마크를 찾고 EAR·눈의 y좌표로 상태를 판단**합니다. 얼굴형 자체는 졸음 조건이 아닙니다.
- 당시 **안경·선글라스에서도 시연이 작동**했다는 것은 사용자 경험이며, 모든 사용자·렌즈·조명에 대한 검증은 아닙니다.
- `test_v2.py`: 약 30초 평균 측정, EAR 0.8, 10프레임, 눈높이+20픽셀. 후기 개발 대화: 3초 측정. 유지 코드에서는 **후기 3초**를 기본값으로 채택했습니다.
- 2단계에는 10초 안팎의 발화 인식·같은 문제 무한 반복이 필요합니다. 3단계는 음량 임계값 미달 시 반복하며, 단계는 1→2→3→1입니다. 네트워크 API 호출에 임의의 10초 제한을 부여하지 않습니다.
- 3단계 계산은 **원시 PCM RMS에 기준값 1을 둔 `20log10` 점수**이며, 물리적으로 보정한 데시벨 SPL이 아닙니다.
- 2023년 최종 시연의 `/home/pi/project/test.py`(약 263줄), 당시 `decibel.py`, WAV 파일, dlib 예측기 모델 자체는 보존된 코드 목록에서 누락되었습니다.
- 모듈 구조, `main.py` 진입점, 일부 예외 처리, 여러 얼굴 중 첫 번째를 선택하는 방식, Google STT의 녹음 후 단발 인식 방식은 **2026년 통합 연결을 위한 선택**이며 원본과 동일함이 확인되지 않습니다.
- 영상·음성 분석이 경고/응답 중 일시 중지된다는 점과 1초 무시 조건은 사용자 설명과 개발 대화의 근거가 있습니다.

## 보존 범위

**`main`은 최종 코드 버전 하나만 보입니다.** 구버전 소스와 단계별 임시 복원본은 `archive/pre-final-cleanup` 브랜치 및 Git 기록에 보존하며, 최종 코드와 한 폴더에 혼합하지 않았습니다. 지금의 최종 코드는 역사적 최종 실행 원본이 아닌 **최종 발표 기준 코드 복원본**입니다.

## 점검 범위

`python3 -m unittest discover -s tests -v`, `python3 main.py --demo`: 정적·순수 로직 확인. 실제 모델·장치·Google Cloud/차량 검증 불가.


## 과거 대화 재감사에서 확인한 추가 차이 (2026-10-31)

- `decibel.py` 후기 원문 일부에 따라 RMS 계산을 **청크별 dB 평균에서 5초 전체 PCM의 단일 RMS**로 수정했습니다. `success.wav` 재생 호출이 확인되어 복원했습니다. 원본 전체 파일은 여전히 없습니다.
- 초반 `test1.py`의 결과별 `result1.wav`(정답), `result2.wav`(오답), `result3.wav`(숫자 미인식)를 2단계 코드에 반영했습니다.
- 후기 `test2.py`에는 STT 전에 별도의 **60 미만 음량 처리**가 있었으나, 원본 완성 시점의 필수 단계인지는 미확정이라 통합 경고의 70 기준과 결합하지 않았습니다.
- 당시 대화에는 초기 1초 재감지 무시와 별도로 10초 `busy` 가드를 시험한 버전이 있습니다. 현재는 1초 조건만 코드에 남기고 충돌 내용을 문서화합니다.

세부 근거와 판정은 [개발 대화 재대조 기록](CONVERSATION_AUDIT_2023.md)을 참조하세요.


## 2026-10-31 최종 기능 설명에 대한 직접 확인 (추가 답변)

1. **눈높이 하강은 두 방식 모두 사용:** 평균 대비 +20픽셀 초과 즉시 감지(A)와 눈높이 하강 상태의 10프레임 누적(B)을 모두 확인했습니다. *동일 +20픽셀 조건*을 두 방식에 그대로 적용하면 A가 항상 먼저 발동해 B는 추가 경고를 발생시키지 않는 중복 조건입니다. 구현에서는 A를 유지하면서 B의 연속 프레임 카운트를 기록합니다. 두 조건의 최종 적용 픽셀 기준이나 순서가 달랐다는 자료는 아직 없으므로 별도 임계값을 만들지 않습니다.
2. **경고 후 재감지:** 1초 무시 뒤 눈을 계속 감고 있으면 바로 다음 단계가 실행됩니다. 한 번 눈을 떠야만 재활성화되는 조건은 없습니다.
3. **2단계 음성 확인:** 약 10초간 **녹음한 후**, 녹음된 음성을 Google STT에 전달해 정답 여부를 판단합니다. 실시간 스트리밍 인식으로 바꾸지 않습니다.
4. **반복 안내 음성:** 2단계 오답/미인식 때 같은 문제의 음성 안내를 다시 재생하며, 3단계 음량 미달 때도 `da.wav`와 `decibel.wav` 안내를 반복합니다. WAV 실제 음원은 미확보입니다.
5. **공통 경고음 우선:** 감지가 발생할 때마다 경고음을 먼저 낸 뒤 1~3단계 중 해당 절차를 진행합니다. 2023년 차량 테스트 화면의 `playy("detect.wav")`에 근거하여 공통 경고음 파일명을 `detect.wav`로 연결합니다. 이 파일이 최종 시연의 정확한 음원이었는지는 원본 통합 코드가 없으므로 추정으로 구분합니다.

경고 순서는 **공통 감지음 → 해당 단계 → 완료 후 다시 영상 분석**이고, 단계 번호는 **1→2→3→1**로 순환합니다. 해당 변경은 최종 발표/사용자 설명을 우선합니다. 실제 실행 하드웨어·WAV 파일은 없어 로직 검증만 진행했습니다.
